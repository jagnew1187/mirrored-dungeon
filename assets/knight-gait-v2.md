# Knight gait v2

Created with the built-in imagegen tool, replacing only Knight walking/standing playback. Source PNGs remain separate and embedded for offline play.

## Final assets

- knight-walk-right-v2.png: eight side-facing poses, including opposite leg half-step correction.
- knight-walk-left-v2.png: separately authored left view, never mirrored at runtime.
- knight-walk-down-v2.png: eight front-facing poses.
- knight-walk-up-v2.png: eight back-facing poses, corrected shield/sword placement.
- knight-idle-v2.png: four planted standing poses, in right/left/down/up order.
- knight-gait-v2.json: source bounds, helmet registration and boot baseline; regenerate with prepare-knight-gait.py (Pillow). Source alpha components determine sprite sampling bounds only, never gameplay collision.

## Playback

combat.js uses KNIGHT_WALK_STRIDE = 88 world pixels per full two-step cycle, replacing the accumulated percentage slowdowns for Knight only. Movement speed, attack/skill timing, damage, collision, race timers and other class animations remain unchanged. Cycles advance with actual travel, stop at collision and preserve phase across stops. Direction uses actual displacement, retains the last direction when standing and has a 25% axis hysteresis band for diagonal input. All directions are authored; no equipment mirroring. Rendering has no added bob over the baked poses.

Frames register at the helmet so planted-boot changes do not recenter the whole body. Full connected-character bounds allow blades outside an approximate source cell without sampling a neighboring character. Walk sheets normalize to the same nominal world height as the previous smaller heroes. New standing artwork uses the matching view immediately on stopping. Attacks and skills retain existing directional side-view art and behavior; four-direction attack artwork is outside this pass.

This is sprite-based contact timing, not a skeletal IK solver: exact pixel-perfect planted-foot locking on every diagonal is not claimed. Visual acceptance should use knight-walk-review.html at game size and the updated game on device. The preview supports pause, standing, speed and frame stepping.

## Validation

Tests cover four travel directions, diagonal hysteresis, distance cadence, stopping/restarting, eight isolated source frames per direction, ground baseline, non-mirrored equipment drawing, matching idle views and preview controls. Existing route, class, combat and mobile-layout checks remain in use. Desktop Chromium mobile viewports exercise touch layouts; this is not a physical iPhone Safari certification.
