# Knight diagonal views v3

Generated with the built-in imagegen tool from the existing Knight standing sheet. New project assets:

- knight-walk-southeast-v3.png: down-right walking and standing.
- knight-walk-southwest-v3.png: down-left walking and standing.
- knight-walk-northeast-v3.png: up-right walking and standing.
- knight-walk-northwest-v3.png: up-left walking and standing.

Each source is a 3×3 atlas: poses 0–7 are walking, pose 8 is planted standing. No direction uses runtime mirroring. The southwest standing sprite was corrected to retain his sword. Existing cardinal sheets are preserved.

assets/knight-art.json owns each sheet path, grid and idle-frame mapping. prepare-knight-gait.py reads that manifest to regenerate knight-gait-v2.json; integrate.cjs and make-knight-preview.cjs consume the same manifest. Source pixels never define gameplay collisions.

Movement now selects the nearest of eight 45-degree sectors from actual resolved displacement. A five-degree overlap retains the previous view near sector boundaries, preventing noisy joystick changes. Stopping retains the last direction and uses that sheet's matching idle. The distance-driven 88px stride, character scale, travel speed and attack/skill mechanics remain unchanged. Attack/skill art still uses the existing side views. The review page has a diagonal/cardinal view selector and correctly projects scrolling ground for diagonal movement.

Validation: test-knight-diagonals.cjs exercises all four diagonal key combinations in desktop and mobile layouts, normalized travel speed, phase continuity, stopping, all source-frame bounds, ground anchors, idle selection, no runtime mirroring and angular hysteresis. Existing cardinal, sprite, combat, route and camp tests also apply. Mobile Chromium layouts are tested; physical iPhone Safari remains a device check.
